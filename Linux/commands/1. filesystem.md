# Linux Filesystem & File Management

This document covers Linux filesystem concepts and file management commands used during my Cloud Infrastructure and DevOps training.

---

## 1. Linux Filesystem

Linux follows a hierarchical filesystem structure with `/` as the root directory.

```text
/
├── bin/       → Essential user commands
├── boot/      → Bootloader and kernel files
├── dev/       → Device files
├── etc/       → System configuration files
├── home/      → User home directories
├── media/     → Mounted media and shared filesystems
├── mnt/       → Common mount point
├── opt/       → Optional software
├── proc/      → Process and kernel information
├── root/      → Root user's home directory
├── tmp/       → Temporary files
├── usr/       → User applications and libraries
└── var/       → Variable data, logs, web files, etc.
````

### Important Directories

|Directory|Purpose|
|---|---|
|`/`|Root of the entire filesystem|
|`/home`|User home directories|
|`/etc`|System and application configuration|
|`/var`|Variable data|
|`/var/log`|System and application logs|
|`/var/www`|Common web server directory|
|`/tmp`|Temporary files|
|`/usr`|User applications and libraries|
|`/dev`|Device files|
|`/proc`|Process and kernel information|
|`/media`|Common location for mounted media/shared filesystems|
|`/mnt`|Common temporary mount location|

# 2. Navigation

## `pwd`

Displays the current working directory.

```bash
pwd
```

Example:

```text
/home/azureuser
```

---

## `ls`

Lists files and directories.

```bash
ls
```

Useful options:

```bash
ls -l
ls -a
ls -lh
ls -lah
```

|Option|Meaning|
|---|---|
|`-l`|Detailed listing|
|`-a`|Show hidden files|
|`-h`|Human-readable file sizes|

---

## `cd`

Changes the current directory.

```bash
cd /var/www
```

Move to the parent directory:

```bash
cd ..
```

Go to the current user's home directory:

```bash
cd ~
```

Go to the previous directory:

```bash
cd -
```

---

# 3. Creating Files and Directories

## `mkdir`

Creates a directory.

```bash
mkdir test
```

Create nested directories:

```bash
mkdir -p project/src/config
```

The `-p` option creates parent directories if they don't already exist.

---

## `touch`

Creates an empty file.

```bash
touch file.txt
```

If the file already exists, `touch` updates its timestamp.

---

# 4. Copying Files

## `cp`

Copy a file:

```bash
cp file.txt backup.txt
```

Copy a file to another directory:

```bash
cp file.txt /tmp/
```

Copy a directory recursively:

```bash
cp -r project/ backup/
```

The `-r` option means **recursive**.

---

# 5. Moving and Renaming

## `mv`

Move a file:

```bash
mv file.txt /tmp/
```

Rename a file:

```bash
mv old.txt new.txt
```

Move a directory:

```bash
mv project/ /opt/
```

---

# 6. Deleting Files and Directories

## `rm`

Delete a file:

```bash
rm file.txt
```

Delete multiple files:

```bash
rm file1.txt file2.txt
```

Delete a directory recursively:

```bash
rm -r directory/
```

Force deletion:

```bash
rm -f file.txt
```

Recursive + force:

```bash
rm -rf directory/
```

> **Warning:** `rm -rf` can permanently delete large amounts of data. Always verify your current directory with `pwd` and its contents with `ls` before using it.

# 7. Viewing Files

## `cat`

Displays the contents of a file.

```bash
cat file.txt
```

Example:

```bash
cat /etc/fstab
```

---

## `less`

Useful for viewing large files.

```bash
less /var/log/syslog
```

Press:

```text
q
```

to exit.

---

## `head`

Displays the beginning of a file.

```bash
head file.txt
```

Display the first 20 lines:

```bash
head -n 20 file.txt
```

---

## `tail`

Displays the end of a file.

```bash
tail file.txt
```

Display the last 20 lines:

```bash
tail -n 20 file.txt
```

Follow a file in real time:

```bash
tail -f /var/log/nginx/access.log
```

This is particularly useful for monitoring NGINX logs.

# 8. Searching for Files

## `find`

Search for a file by name:

```bash
find /var/www -name "index.html"
```

Search from the current directory:

```bash
find . -name "*.jpg"
```

Search for directories:

```bash
find . -type d -name "logs"
```

Search for files:

```bash
find . -type f -name "*.conf"
```

### Common `find` options

|Option|Purpose|
|---|---|
|`-name`|Search by name|
|`-type f`|Search for files|
|`-type d`|Search for directories|
|`-size`|Search by file size|
|`-mtime`|Search by modification time|

---

# 9. Searching Inside Files

## `grep`

Search for text:

```bash
grep "error" logfile.txt
```

Search recursively:

```bash
grep -r "server_name" /etc/nginx/
```

Ignore case:

```bash
grep -i "error" logfile.txt
```

Show line numbers:

```bash
grep -n "error" logfile.txt
```

# 11. Disk Usage

## `df`

Displays filesystem disk usage.

```bash
df -h
```

The `-h` option displays human-readable values.

Example:

```text
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda2        30G   10G   20G  34% /
```

### Why `df -h` is useful

It can be used to:

- Check available disk space
    
- Identify full filesystems
    
- Verify mounted filesystems
    
- Verify Azure File Share mounts
    

For example:

```bash
df -h
```

An Azure File Share mounted through SMB/CIFS may appear in the output.

---

## `du`

Displays disk usage of files and directories.

```bash
du -sh directory/
```

Display the size of items in the current directory:

```bash
du -sh *
```

|Command|Purpose|
|---|---|
|`df -h`|Filesystem-level disk usage|
|`du -sh`|Directory/file-level disk usage|

# 12. Mount Points

Linux can attach external filesystems to directories called **mount points**.

For example, an Azure File Share can be mounted like:

```text
Azure File Share
       │
       │ SMB/CIFS
       ▼
/media/webfiles
       │
       ▼
Linux filesystem
```

The directory `/media/webfiles` acts as the access point to the remote Azure File Share.

# 13. Persistent Mounts

The `/etc/fstab` file contains filesystem mount configurations that can be automatically mounted during system startup.

View it using:

```bash
cat /etc/fstab
```

or:

```bash
sudo nano /etc/fstab
```

An Azure File Share can be configured in `/etc/fstab` so that:

```text
VM boots
   ↓
/etc/fstab
   ↓
Azure File Share mounted
   ↓
Applications can access the files
```

This means the mount can survive a VM reboot.
